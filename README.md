# Discord_AI_bot · 도리봇

도리봇은 금칙어·링크 검열, XP·레벨·업적과 면제권, 커스텀 이모지,
AI 질문과 그림 생성을 지원하는 discord.py 봇입니다.
원본: [discordbot-main](https://github.com/diligencefrozen/discordbot-main).

## 실행

대상 런타임은 Python 3.13, Discord 라이브러리는 `discord.py==2.7.1`입니다.
`.env.example`을 `.env`로 복사하고 `DISCORD_TOKEN`, `GEMINI_API_KEY`를 설정하세요.
기존 호스팅의 다른 토큰·설정 전체를 이 예시 파일로 덮어쓰지 마세요.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py
```

V6에서 `SLASH_SYNC_ON_STARTUP` 미설정/`auto`는 원격 명령을 조회하고 누락·옛 `/ai질문`·
기본 권한 제한이 있으면 안전 검증 후 전역 명령을 복구합니다. `1`은 강제 게시, `0`은 조회만 합니다.
로컬 명령의 이름·개수·종류, Application ID/Bot ID와 원격 소유 범위를 확인하며,
예상 밖 명령이나 조회 실패가 있으면 전체 덮어쓰기를 중단합니다.
로컬 명령·버튼 등록은 `setup_hook`에서 수행하며 게이트웨이 재연결은 전역 동기화를 일으키지 않습니다.
동기화 실패는 자동 반복하지 않습니다. `/관리`의 `guild_only`는 DM 사용 금지이며,
별도의 특정 서버 명령 등록을 의미하지 않습니다.

`!` 명령은 유지됩니다. `/시작`, `/질문`, `/그림`, `/내정보`, `/관리`와
타이핑 알림의 4개 버튼도 지원합니다. 타이핑 안내문과 2×2 버튼은 Components V2의
하나의 컨테이너에 표시됩니다. 감지 지연 기본값은 **1.3초**입니다.
안내 배치는 **표시이름 인사 → 짧은 도움말 → 구분선 → 도리봇 제목 → 버튼 2행**입니다.
맨 위에 `👀 표시이름님, 채팅을 작성 중이셨네요!`를 표시하고 행 사이에는 보이지 않는 Separator로 여백을 둡니다.
표시이름은 짧게 제한하고 Markdown·멘션을 이스케이프하며 자동 핑은 하지 않습니다.
버튼 폭·가로 간격은 Discord 클라이언트가 정하며 모바일 실제 배치는 운영 검증 대상입니다.
`TYPING_INTRO_DELAY_SECONDS`는 0.1~1.5초의 유한한 값만 허용하며 잘못된 값은 기본값으로 돌아갑니다.
첫 타이핑 타이머를 후속 이벤트가 연장하지 않고 메시지 기록 조회도 하지 않습니다.
자동 안내는 **사용자×서버별 마지막 성공 전송 후 24시간에 한 번**입니다. 같은 서버의 채널·스레드 이동은
제한을 공유하지만 다른 사용자의 안내를 막는 채널 전체 제한은 없습니다. 다른 서버는 독립적입니다.
메시지를 먼저 보내면 타이핑 타이머를 취소하고 검열을 통과한 일반 메시지에 보조 안내를 적용합니다.
작성 중 멈춘 경우 첫 이벤트 타이머가 한 번 실행됩니다. 봇·DM·명령·검열된 메시지에는 보조 안내를 보내지 않습니다.
Discord가 타이핑 이벤트를 보내는 시각이나 실제 네트워크 전송 완료를 1.5초 이내로 보장하는 것은 아닙니다.
구형 채널 기록은 서버×사용자로 합치고, 서버 정보 없는 `user:<id>` 기록은 기존 24시간이 만료될 때까지만
보수적으로 이어받습니다. 이후 성공 전송부터 새 서버별 키를 사용합니다.

## XP와 보상

검열을 통과한 서버의 일반 사용자 메시지만 적격입니다. 봇·DM·접두사 명령·중복 이벤트와
5초 XP 쿨다운 내 메시지는 활동 XP와 적격 메시지 수를 늘리지 않습니다.
평일(월~목)은 25, 주말(금~일)은 45 활동 XP입니다. 등급 기준은 30/90/180/300/450 활동 XP로,
당일 조건이 일정할 때 전설은 **평일 18회 / 주말 10회**의 적격 메시지가 필요합니다.
날짜와 주말은 Asia/Seoul 기준이며 자정에 일일 XP·업적·보상 상태가 초기화됩니다.

등급·보상·전설은 `activity_xp`만 판단합니다. 업적의 `bonus_xp`는 등급을 올리지 않습니다.
표시되는 총 XP(`xp`)는 활동 XP + 업적 보너스 + 이행 전 보존 XP(`legacy_xp`)입니다.
보너스가 업적 평가를 재귀 호출하지 않으며 한 입력에서 넘은 모든 등급의 보상을 한 번씩 처리합니다.
VIP 축하는 **각 사용자·날짜별 최대 한 번**이며 서버 전체에서 하루 한 명을 선정하는 정책이 아닙니다.

기존 Pickle 총점은 활동·보너스를 정확히 복원할 근거가 없어 `legacy_xp`로 보존합니다.
기존 수령·면제권·업적도 유지하고, 이행 당일 새 활동 XP는 0에서 시작합니다. 사용자 데이터를 일괄 삭제하지 않습니다.
배포 전 파일과 백업을 보관하고 오늘의 잘못된 기록을 정리할지는 운영자가 선택하세요.
자세한 백업·선택 정리 절차는 [운영 문서](docs/NORTHFLANK_OPERATIONS.md)에 있습니다.

## AI 질문과 그림

질문은 `TEXT_AI_PROVIDER=gemini`, `GEMINI_TEXT_MODEL=gemini-3.5-flash-lite`,
`GEMINI_API_KEY`를 사용합니다. `!ask`, `/질문`, 버튼·전체 메뉴의 질문이 같은
Gemini 함수와 요청 제한기를 사용합니다. 키가 없거나 잘못되면 질문만 안전하게 실패하며,
검열·XP·그림 기능은 계속 사용할 수 있습니다. 자동 재시도나 다른 제공자로의 전환은 없습니다.
[공식 모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite).

응답 시간 초과의 운영 완화값은 `GEMINI_TIMEOUT_SECONDS=60`입니다. 코드의 미설정 기본값은
기존 30초로 유지됩니다. httpx의 connect/read/write/pool 단계별 제한이므로 전체 요청이 반드시
60초 안에 끝난다는 뜻은 아닙니다. 이는 임시 완화이며 원인이 Google 지연·네트워크·프록시 중
무엇인지 증명하지 않습니다. `event=gemini_request_start/end` 로그의 `elapsed_ms`, `result`,
`http_status`, `timeout_phase`로 구분하세요. 로그에는 프롬프트·키·응답 원문을 남기지 않습니다.
질문 인터랙션은 HTTP 호출 전에 비공개 defer하여 Discord의 초기 응답 제한을 지킵니다.

**AI 답변은 요청한 채널에 공개됩니다.** 질문 모달에 제출 전 공개 안내가 표시됩니다.
질문 원문을 별도 재게시하지 않으며, 완료 확인·검열 거부·API 오류는 인터랙션에서 비공개로 표시됩니다.
긴 답변은 전체 UTF-8 텍스트 파일로 공개하여 코드블록이나 내용을 잘라내지 않습니다.
알림 멘션은 요청자에게만 허용합니다. `!ask`는 기존 공개 답변을 유지하며,
접두사 명령의 오류 안내는 Discord의 ephemeral 응답을 지원하지 않아 채널에 안전한 문구로 표시됩니다.
내 성장·전체 메뉴·관리 정보는 계속 비공개입니다.

그림(`!img`, `/그림`, 그림 버튼)은 **항상 AI Horde**를 사용합니다.
`AI_PROVIDER=aihorde`는 기존 배포 호환 설정이며 `AI_BACKEND`도 제공자를 바꾸지 않습니다.
Horde 키가 비어 있으면 기존 익명 키를 사용합니다.
키 우선순위는 `AI_HORDE_API_KEY` > `HORDE_API_KEY` > `AIHORDE_API_KEY`,
이미지 모델은 `HORDE_IMAGE_MODEL` > `AIHORDE_IMAGE_MODEL`입니다.
`HF_TOKEN`·`HF_IMG_TOKEN`은 이 AI 경로에 쓰이지 않으며 마이그레이션 중 기존 환경에서 임의 삭제하지 않습니다.

기본 로컬 방어 한도는 분당 15회·일 500회·사용자별 10초입니다.
`GEMINI_RPM_LIMIT`, `GEMINI_RPD_LIMIT`, `GEMINI_USER_COOLDOWN_SECONDS`로 조정합니다.
메모리 카운터는 재시작 시 초기화되고 실제 프로젝트 한도나 TPM을 대신하지 않습니다.
무료 프로젝트 상태와 현재 한도는 운영자가 [AI Studio](https://aistudio.google.com/rate-limit)에서 확인해야 합니다.
질문과 시스템 지침은 Google에 전송되며, 무료 등급 데이터는 제품 개선에 사용될 수 있습니다.
[가격·데이터 처리 조건](https://ai.google.dev/gemini-api/docs/pricing),
[사용량 제한](https://ai.google.dev/gemini-api/docs/rate-limits).

## 파딱과 금칙어 조회

파딱은 '파란 딱지'의 준말입니다. 런타임 환경에 두 계정을 모두 등록하세요.

```dotenv
SPECIAL_ADMIN_USER_ID=855749166764654653
SPECIAL_ADMIN_USER_IDS=855749166764654653,491239880005910538
```

구형 단일 ID와 복수 ID를 합집합으로 병합하고 중복 정수 ID를 제거합니다.
비어 있으면 서버 소유자만 허용하고, 어느 설정이든 잘못된 값이 있으면 파딱 예외를 모두 거부합니다.
`SPECIAL_ADMIN_GUILD_IDS`는 파딱의 서버 범위를 제한하며 서버 소유자의 기존 접근은 유지합니다.
DM·역할·Administrator 권한·닉네임은 관리 권한을 부여하지 않습니다.
각 버튼·모달·페이지 이동에서 권한을 다시 확인합니다.

`/관리 → ⚙️ 금칙어`는 실제 활성 목록과 `N개`, 이전/다음 페이지를 비공개로 표시합니다.
정확히 같은 원문만 중복 제거하므로 기존 `fuck`, `Fuck`, `FUCK`도 모두 표시됩니다.
목록은 `moderation_rules.BAD_ROOTS` 하나에서 가져오며 추가·삭제 기능은 없습니다.
`/관리`는 사용자 관리 / 채널 관리 / 금칙어·테스트 / 관리 기록·상태로 이동하는 비공개 패널입니다.
회원 선택 후 타임아웃·해제, 서버 별명 변경·초기화, 밴·수동 밴 해제·추방을 확인 화면에서 실행합니다.
V6의 노출된 관리 조치는 **일반 Discord 역할인 파딱도 ID 인증으로 봇의 권한을 위임받아** 실행합니다.
실행자의 서버 관리 권한·역할 우위를 요구하지 않습니다. 버튼·모달·확인·실행 서비스에서 ID/서버 인증을 반복하며,
봇 자신의 Discord 권한·역할 우위·현재 채널 접근과 보호 대상 검사는 유지합니다.
메시지 정리(`cleanup`)는 사용자 관리 선택 메뉴에서만 숨기고 오래된 선택 UI도 비공개 거부합니다.
서비스·검증·모달·실행·공통 삭제 경로는 향후 재사용을 위해 보존하고 기존 실행자 권한/역할 검사도 유지합니다.
채널 슬로우모드와 잠금/상속 해제를 지원하며 스레드 슬로우모드는 봇의 스레드 관리 권한을 검사합니다.
잠금은 `@everyone.send_messages=False`, 해제는 `None`으로 상속합니다. 다른 overwrite는 보존하고
잠금 이전의 명시적 True/False 복원이나 모든 역할·스레드의 완전한 대화 차단을 보장하지 않습니다.
경고·조회는 서버/대상별 메모리 기록이며 재시작하면 초기화됩니다.
다른 파딱·본인·봇·서버 소유자 등 보호 대상에는 조치를 실행하지 않습니다. Discord Administrator에게는 타임아웃을 적용할 수 없습니다.
최근 관리 기록은 최소 메타데이터만 담는 메모리 버퍼이며 재시작하면 초기화됩니다.
`MOD_LOG_CHANNEL_ID`는 같은 서버의 별도 기록 채널을 지정하는 선택값입니다.
운영 상태는 금칙어 개수·저장 경로/쓰기 가능 여부·로컬 등록과 이번 프로세스 게시 상태를 표시합니다.
서버 별명과 native timeout·밴·슬로우모드는 Discord에 적용되어 봇 재시작 후에도 유지됩니다.
임시 밴 자동 해제·역할 지급·메시지 고정·장기 경고/기록·필터 실시간 변경은 이번 범위에서 제외합니다.

`/관리`가 명령 선택기에 없으면 다음 네 층을 따로 확인하세요.

1. **등록/게시:** 로컬 5개 등록과 원격 게시 성공 로그, 올바른 Application ID·Bot ID, 한 replica를 확인합니다.
   기본 `auto`로 진단/복구하고, 조회만 원하면 `0`, 명시적 재게시에는 `1`로 시작한 뒤 `auto`로 돌립니다.
   의도한 목록 밖 원격 명령이 있으면 덮어쓰기를 중단하므로 삭제하지 말고 운영 구성을 확인하세요.
2. **Discord 권한:** 서버 앱 설치의 `applications.commands` 범위, 서버 설정 → 연동 → 도리봇 → 명령 권한,
   사용자/역할/채널의 애플리케이션 명령 사용 권한을 확인합니다.
   [Discord 명령 권한 안내](https://support-apps.discord.com/hc/en-us/articles/26501869403159-Command-Permissions).
3. **환경변수:** 위 두 ID·선택 서버 범위와 배포 후 실제 프로세스 재시작을 확인합니다. 값에 리터럴 따옴표·잘못된 쉼표·빈 항목을 넣지 마세요.
   `event=admin_configuration`의 유효성·ID 개수·사유 코드만 확인하고 비밀값을 덤프하지 않습니다.
4. **서버 인증:** 실제 명령 선택 후 `event=admin_open result=allowed|denied reason=... source=slash`를 확인합니다.
   DM, 특수관리자 서버 범위 밖, 잘못된 ID 설정 등은 별도 거부 원인입니다. 소유자 접근은 유지합니다.

일반 채팅으로 입력한 `/관리`는 슬래시 상호작용이 아닙니다. 도리봇은 하루 한 번 선택 방법만 안내하고 관리 작업이나 XP 지급을 하지 않습니다.
`guild_only`는 DM 실행을 막으며 특정 서버만 등록한다는 뜻은 아닙니다. 로컬 테스트로 실제 Discord 선택기 표시를 보장할 수 없습니다.

## 데이터와 배포

SQL/외부 DB 없이 `daily_xp_data.pkl`, `achievements_data.pkl`을 유지합니다.
`DATA_DIR`(구형 `STATE_DIR` 호환)에 영속 볼륨을 연결하면 Pickle·백업·타이핑 쿨다운·집계 지표가 보존됩니다.
타이핑 공지의 24시간 기록을 재시작·재배포 후에도 유지하려면 영속 볼륨을 사용하고 봇을 한 인스턴스로 실행하세요.
금칙어와 링크가 함께 위반되어도 메시지/프롬프트당 면제권은 최대 1회 사용합니다.
시간제 `all`·`trial`은 횟수를 줄이지 않습니다. 콘솔·예외 텔레메트리·장기 상태 파일에는 메시지 원문을 남기지 않습니다.

## 공용 삭제 기록과 접근 범위

V8은 기존 네 서버의 **공용 기록 채널 한 곳씩**을 유지하고, 기존에 보이던 **User·Channel·메시지 ID**를 복원합니다.
이 공개 정책은 [V8 복원·운영 결정표](docs/DELETE_LOG_LEGACY_RESTORE_V8_2026-10-23.md)가 기준이며 V7의 익명 카드 정책을 대체합니다.
**서버 콘솔은 ID·결과·사유 코드·단계·예외 타입만** 기록하고 원문은 Discord 카드에서 허용된 경우에만 보여 줍니다.

기존 `LOG_ROUTES`/`CHANNEL_TO_LOG` 매핑과 채널 ID를 유지합니다. `DELETION_PUBLIC_LOG_ENABLED=1`과
`DELETION_PUBLIC_LOG_INCLUDE_CONTENT=1`이 기본입니다. `0` 또는 잘못된 값은 해당 기능을 끕니다.
`DELETION_LOG_ALL_GUILD_CHANNELS=1`은 같은 서버의 기존 단일 수신지로 신규 일반 채널도 연결하며,
필요하면 `DELETION_LOG_EXTRA_SOURCE_CHANNEL_IDS`에 추가 소스를 지정합니다. 수신지를 임의로 만들지 않습니다.
출력 수준은 다음 세 단계로 결정합니다.

1. **명시 `LOG_ROUTES` 원본:** 비공개이거나 권한 범위를 확인하지 못해도 확보된 작성자 이름·ID, 원본 채널 이름·ID,
   메시지 ID, KST 확인 시각, 삭제 유형·사유 코드를 남깁니다. 원문·실제 탐지 문자열·첨부파일 이름은 기본적으로 숨깁니다.
   이 기본 기록도 비공개 채널의 존재·작성자·활동을 공용 기록 열람자에게 공개하므로 운영자가 대상 매핑과 보존 기준을 검토해야 합니다.
2. **독자 범위가 검증된 원본:** 로그 열람자가 원본 열람자의 부분집합임을 역할 조합·멤버 overwrite까지 증명하면 상세 카드를 보냅니다.
   원문 `시321133발`, 실제 일치 금칙어, 파일 메타데이터와 메시지 ID는 서로 별도로 표시합니다.
3. **명시 비공개 원본의 본문 공개 동의:** `DELETION_PUBLIC_LOG_PRIVATE_FULL_SOURCE_IDS`에 해당 원본 ID를 직접 등록한 경우에만
   상세 공개를 선택할 수 있습니다. 기본값은 빈 값이며 `LOG_ROUTES` 밖 ID는 무시합니다.
   비공개 본문·탐지 문자열·파일명까지 공용 채널에 재게시하는 강한 공개 설정이므로 일괄 활성화하지 마세요.

명시 매핑에 없는 자동 감시/추가 원본은 독자 범위가 검증될 때만 전송하며 비공개·권한 불명 상태에서는 카드 자체를 보내지 않습니다.
실물 discord.py의 미캐시 `discord.Object(type=discord.Role/Member)` overwrite도 구분하고,
채널 보기와 무관한 overwrite 때문에 공개 채널을 비공개로 오판하지 않습니다.
DM·스레드·다른 서버 수신지·로그 채널 자신으로의 라우팅을 거부합니다.
봇의 채널 보기·메시지 보내기·링크 임베드 권한도 필요합니다.
역할/개별 사용자 접근을 자동으로 열거나 기존 채널 ID를 변경하지 않습니다.
옛 `DELETION_LOG_INCLUDE_CONTENT`, 비공개 로그 라우팅/신뢰 역할 설정은 V8 판단에 사용하지 않습니다.
`/관리`는 `sent_full`, `sent_metadata_only`, `sent_restricted`, `failed`, `skipped`를 분리하고 마지막 상세 전송을 KST로 표시합니다.
전송 테스트는 원문 없는 합성 카드 한 건의 송신 검사이며 실제 삭제 처리 확인과 구분합니다.
`sent_full`은 실제 상세 본문을 전송한 경우이며 기본 기록은 `sent_metadata_only`입니다. 기본 기록을 상세 성공으로 집계하지 않습니다.
전역 `DELETION_PUBLIC_LOG_INCLUDE_CONTENT=0`은 개별 본문 공개 동의가 있어도 콘텐츠를 가립니다.

상세 카드는 작성자·위치·삭제 확인 시각(KST)·확인 가능한 사유, 원문, 이모지·스티커,
이미지/영상/GIF/오디오/문서/압축파일 등의 이름·MIME·크기·해상도·스포일러·ID와 임베드 메타데이터를 보여 줍니다.
항목이 많거나 길면 표시 개수/문자 수와 생략 사실을 표시합니다. 없는 콘텐츠를 추측하지 않고,
빈 원문과 **확인 불가(캐시/스냅샷 없음)**를 구분합니다. Unicode 이모지는 원문에 보존하지만 별도 목록 분석은 일부만 지원합니다.

봇 삭제는 API 호출 전에 원문과 사유를 메모리에 확보합니다. 일반·raw·일괄 삭제와 관리자 메시지 정리도
같은 경로에서 메시지 ID로 중복 제거합니다. 외부 삭제의 실행자가 사용자 본인인지 운영진인지는 단정하지 않습니다.
삭제 실패를 삭제 성공으로 표시하지 않으며 감사 전송 실패가 기존 검열 삭제를 막지 않습니다.
메시지 수정은 새 스냅샷을 반영하고 불완전한 raw 수정은 이전 원문을 무효화합니다.

스냅샷 캐시는 **프로세스 메모리 최대 256개·10분**, 전송 중복 기록은 **최대 4096개·10분**입니다.
원문을 가진 대기/삭제 처리 작업은 각각 최대 64개, 동시 감사 발송은 4개로 제한합니다. 처리 중인 참조는 작업 종료까지 남을 수 있습니다.
카드의 삭제 확인 시각은 봇이 이벤트나 삭제 성공을 관찰한 KST 시각이며 Discord가 제공하지 않는 서버 내부 삭제 시각을 추정하지 않습니다.
재시작·캐시 만료·한도 초과 시 원문을 복원하지 못할 수 있습니다. 본문/첨부 URL을 Pickle·JSON·SQLite나 콘솔에 저장하지 않습니다.
첨부파일을 다운로드·재업로드·아카이빙하지 않으며 삭제 후 URL·프록시 URL·미리보기의 유지를 보장하지 않습니다.
Discord에 전송된 감사 카드는 메모리 만료와 별개로 남습니다. 운영자는 채널 열람자와 보관 기간을 정하고,
필요한 기간이 지난 카드를 Discord에서 삭제해야 합니다. 자동 장기 보존/자동 삭제 스케줄러는 없습니다.

실제 Northflank 변수 변경·토큰 교체·스테이징 검증은
[운영 절차](docs/NORTHFLANK_OPERATIONS.md), 구현과 검증 범위는
[구현 상태](docs/IMPLEMENTATION_STATUS.md)를 참고하세요.

## 수정 즉시 검열과 주기적 재검사

`on_raw_message_edit`는 수정 **후** 원문을 즉시 검열하고 캐시 수정 이벤트와 원장을 공유합니다.
새 메시지와 같은 금칙어·링크·채널 예외·면제권 정책을 사용하며 부분 이벤트는 필요한 경우 현재 메시지를 조회합니다.
임베드만 바뀐 이벤트는 제외합니다. 동일 수정본의 중복 이벤트는 면제권/삭제를 반복하지 않고,
XP·업적·AI·타이핑 안내를 재실행하지 않습니다. 삭제 카드는 수정 검열/과거 재검사 트리거를 구분합니다.

별도로 `EDIT_MODERATION_SCAN_ENABLED=1`이면 READY 후 기본 45초 대기한 단일 작업이
**72시간마다 생성 시각 기준 최근 96시간**을 검사합니다. 최근 48시간을 모든 채널에서 먼저 검사한 뒤
48~96시간을 검사합니다. 채널당 최대 2,000개·전체 20,000개, 기본 동시성 1이며 한도 도달은 부분 검사로 표시합니다.
조회 범위를 주기보다 좁게 설정하면 공백을 경고하고 보정합니다. 재검사는 면제권을 소비하지 않습니다.
과거 미수정 메시지의 면제 여부는 단정할 수 없어 보수적으로 건너뛰며, 현재 면제권이 있는 수정본도 보존합니다.
`/관리 → 수정 검열 상태`에서 서버별 건수·마지막/다음 시각·제외/실패 사유를 확인합니다.
이벤트/검사 원장은 본문 해시·ID·결과만 메모리에 보존하고 재시작 시 초기화됩니다.
온라인 raw 이벤트는 오래된 메시지의 수정도 처리하지만, 오프라인 동안 수정된 생성 후 96시간 밖의 메시지나
조회 한도·권한·캐시 밖 누락을 완전히 복구할 수는 없습니다. 수정 이벤트와 주기 검사는 둘 다 필요합니다.


공용 삭제 기록의 최신 정책·소스별 결정·배포 점검: [`docs/DELETE_LOG_LEGACY_RESTORE_V8_2026-10-23.md`](docs/DELETE_LOG_LEGACY_RESTORE_V8_2026-10-23.md).
V7 문서는 이전 수정 이력으로만 보관하며 익명 제한 카드 정책을 현재 정책으로 적용하지 않습니다.
