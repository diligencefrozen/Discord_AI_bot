# Northflank 운영 절차 — 명시 채널 원문 공개·간결한 카드 / V6 기능 유지

공용 삭제 기록은 [2026-10-23 원문 공개·간결한 카드 정책](DELETION_LOG_COMPACT_POLICY_2026-10-23.md)을 우선 적용합니다.
운영자가 **기존 `LOG_ROUTES`의 모든 원본 채널**에 대해 일반 회원이 삭제 원문을 볼 수 있도록 승인했습니다.
명시 비공개 원본도 포함하며 V8의 본문 기본 생략 정책을 대체합니다. 다른 V6 기능·권한·저장 정책은 유지합니다.
V7의 실물 discord.py 2.7.1 권한 오판·REST 복구 검증은 이력으로 유지하며, 운영 Northflank/Discord 결과는 별도 UNKNOWN으로 기록합니다.

갱신: 2026-10-23 (Asia/Seoul). 삭제 기록은 운영자의 최신 공개 범위·UI 요청을 적용하며 다른 기능은 V6 지시를 보존합니다.
이 문서는 운영자가 적용할 절차이며, 이 작업에서 Northflank 설정 변경·배포 또는 실제 Discord 검증을 수행한 것은 아닙니다.
로컬 테스트, 원격 명령 게시, 실계정 검증, 운영 배포를 각각 기록하세요. 최종 테스트 수는 구현 상태 보고서에서 확인합니다.

## 배포 전 확인과 파일 보존

1. 현재 운영 커밋·배포 이미지·설정 이름과 후보 커밋을 기록합니다. 이전 ZIP으로 최신 작업 브랜치를 덮어쓰지 않습니다.
2. 목표 런타임은 Python 3.13, `discord.py==2.7.1`이며 `requirements.txt` 설치 후 `python main.py`로 실행합니다.
   이번 로컬 검증 환경은 Python 3.12.14와 discord.py 2.7.1입니다. Python 3.13 빌드·시작 확인은 배포 과정에서 별도로 수행합니다.
3. 한 replica만 실행합니다. 같은 봇 토큰을 쓰는 구/신 프로세스를 동시에 실행하지 않습니다.
4. 봇을 잠시 중지한 뒤 `daily_xp_data.pkl`, `achievements_data.pkl`, `.bak.1`~`.bak.3`, `typing_cooldowns.json`을 서비스 외부에도 백업합니다.
5. 실제 영속 볼륨을 `/data`에 마운트한 경우에만 `DATA_DIR=/data`를 설정합니다. `STATE_DIR`는 하위 호환 별칭이며 `DATA_DIR`가 우선합니다.
   볼륨 없이 경로 문자열만 설정해도 파일이 영구 보존되지는 않습니다.
6. 최초 이행은 영속 경로에 없는 기존 CWD Pickle·백업을 복사하고 기존 영속 파일을 덮어쓰지 않습니다.
   Pickle·타이핑 상태는 기존 원자적 저장·백업 경로를 유지합니다. SQL이나 외부 DB는 필요하지 않습니다.
7. 실제 토큰·API 키·환경설정 전체를 채팅·Git·stdout에 복사하지 않습니다. 봇 토큰 이름은 `DISCORD_TOKEN`입니다.
   다른 서비스의 구형 토큰 변수를 사용처 확인 없이 삭제하지 않습니다.

Discord가 저장하는 timeout·서버 별명·밴·추방·슬로우모드·채널 overwrite는 봇 재시작 후에도 유지됩니다.
최근 관리 기록, 임시 경고, 확인 토큰, 삭제 스냅샷·중복 기록, 수정 검열·스캔 상태와 Gemini 로컬 카운터는 메모리 상태이므로 재시작 시 초기화됩니다.

| `DELETION_LOG_ALL_GUILD_CHANNELS` | `1` | 기존 기록 목적지가 하나로 확인되는 같은 서버의 추가 공개 텍스트 채널을 안전하게 포함 |

| `EDIT_MODERATION_SCAN_CONCURRENCY` | `1` | 유효 범위 1~4. REST 부하를 고려해 기본 1 유지 |

| `MOD_LOG_CHANNEL_ID` | 선택 / 기존 값 유지 | 관리 조치 ID·작업·결과 메타데이터용. 삭제 원문 목적지를 추가하지 않음 |

삭제 기록의 불리언 설정은 `1`일 때만 활성화됩니다. 잘못된 값은 해당 설정을 끕니다.
추가 원본/본문 공개 ID에 따옴표·비숫자·빈 항목·끝 쉼표가 있으면 해당 목록을 거부합니다. 기존 `LOG_ROUTES` 자체는 보존됩니다.
명시 원본 전체 공개의 미설정 기본값은 `1`입니다. 현재 `ENABLED=1`, `INCLUDE_CONTENT=1`이면 새 코드 배포 후 전체 ID 목록을 작성하지 않아도 확보된 원문을 표시합니다.
`PRIVATE_FULL_SOURCE_IDS`를 비우는 것만으로 전체 명시 원본 공개가 꺼지지 않습니다. V8 복귀에는 반드시 `REGISTERED_SOURCE_CONTENT=0`을 설정하세요.
메시지 삭제 검열을 유지하면서 모든 본문을 가리려면 `INCLUDE_CONTENT=0`을 사용합니다.
수정 검열 숫자 설정은 유한한 유효 범위만 허용하고 잘못된 값은 안전한 기본값으로 처리합니다.

구형 `DELETION_PRIVATE_AUDIT_ROUTES`, `DELETION_LOG_INCLUDE_CONTENT`, `DELETION_LOG_TRUSTED_ROLE_IDS`는 현재 삭제 기록에 영향을 주지 않습니다.
운영 설정에서 정리할 수 있지만 이 변수들을 지워도 새 채널을 만들 필요는 없습니다. 원문 스위치는 `DELETION_PUBLIC_LOG_INCLUDE_CONTENT`입니다.

기존 Gemini/Horde 설정은 변경하지 않습니다. 질문은 Gemini, 그림은 Horde이며 기존 제한·안전성·접두사 명령을 유지합니다.
`GEMINI_API_KEY`는 Northflank secret에 보관하고 기존 `GEMINI_TEXT_MODEL`, RPM/RPD, 사용자 쿨다운을 보존합니다.
`GEMINI_TIMEOUT_SECONDS=60`을 사용 중이라면 유지하되, 이는 HTTP 단계별 제한이며 전체 요청 완료 시간을 보장하지 않습니다.
Horde 키 우선순위는 `AI_HORDE_API_KEY` > `HORDE_API_KEY` > 구형 `AIHORDE_API_KEY`입니다.
`HORDE_IMAGE_MODEL`이 구형 이미지 모델 변수보다 우선하며 이미지 동시성·용량·허용 호스트 보호를 유지합니다.

## 파딱 인증과 봇 대리 실행

두 파딱 ID는 일반 회원 역할인 상태로 `/관리`와 하위 조치를 사용합니다. 실행자에게 `Administrator`, `Ban Members`, `Moderate Members`, `Manage Channels`를 부여해서 해결하지 않습니다.
서버 소유자 또는 유효한 설정의 정확한 사용자 ID만 허용하며, 역할·별명·표시명 자체는 자격을 만들지 않습니다.
DM·범위 밖 서버·제3자는 거부합니다. 단일/복수 ID 중 비어 있지 않은 설정이 잘못되면 파딱 예외 전체를 fail closed 처리하고 서버 소유자 경로는 유지합니다.
리터럴 따옴표·전각 쉼표·연속/끝 쉼표·빈 항목은 오류이며 쉼표 양쪽의 일반 공백은 허용됩니다.

봇은 준비와 최종 실행 때 인증·서버·대상·권한을 재검사합니다. 확인은 요청자·서버·작업에 묶인 120초 단회 토큰입니다.
현재 노출된 조치는 실행자의 native 관리 권한·대상보다 높은 역할을 요구하지 않고 봇 자신의 권한·역할을 사용합니다.
본인·봇·서버 소유자·다른 파딱·Discord Administrator·봇과 동급/상위 역할인 대상은 보호합니다.
현재 채널 도구는 원래 채널 문맥에 묶이고 실행자가 그 채널을 실제로 볼 수 있어야 합니다. 숨김 채널을 열어 주거나 새 채널 목록을 제공하지 않습니다.

| 조치 | 봇 권한·의미 | 지속성 / 유의사항 |
| --- | --- | --- |
| 타임아웃/해제 | `Moderate Members`; 1/5/10분, 1시간, 1/7/28일 | native timeout으로 Discord에 만료 저장. 최대 28일 |
| 서버 별명 변경/초기화 | `Manage Nicknames`; 1~32자·변경 전후 확인 | 해당 서버만 변경. 전역 계정명 변경 아님 |
| 영구 밴/수동 해제·추방 | `Ban Members` / `Kick Members` | 밴은 `delete_message_seconds=0`. 과거 정상 글을 함께 삭제하지 않음 |
| 슬로우모드 | 일반 채널 `Manage Channels`, 스레드 `Manage Threads` | 현재 값과 변경값 표시. 0초는 해제 |
| 현재 채널 쓰기 잠금/상속 | `Manage Roles`, 현재 일반 텍스트 채널 | `@everyone.send_messages`만 변경. 다른 overwrite 필드는 보존 |
| 임시 경고·조회 | 봇 내부 카운트, 별도 자동 제재 없음 | 서버×회원별 횟수·최근 시각·조치자. 합계 최근 1000명 한도, 오래된 대상 삭제·재시작 초기화 |
| 최근 관리 작업 | 원문 없는 ID·작업·시각·결과 | 최근 15건 표시, 기본 최대 200건 메모리. 재시작 초기화 |

쓰기 잠금은 `send_messages=False`, 해제는 `send_messages=None`으로 **상속**합니다. 잠금 이전 값의 정확한 복원 기능이 아닙니다.
별도 역할의 명시적 쓰기 허용이나 Administrator 예외가 있으면 일부 회원은 계속 쓸 수 있으므로 확인 화면의 영향 범위를 확인하세요.
다른 overwrite 변경을 되돌리는 전체 덮어쓰기나 역할 권한 일괄 변경은 하지 않습니다.

`cleanup`은 `/관리 → 사용자 관리` Select에서만 숨겨졌습니다. 이전 Select의 `cleanup` 값도 UI 콜백에서 비공개 거부합니다.
`ACTION_LABELS`, `PERMISSIONS`, 미리보기, 검증, 실행, 모달, `delete_service`와 감사 경로는 장래 재사용을 위해 보존합니다.
이 숨김 서비스의 기존 실행자 `Manage Messages`·역할 우위·기록 조회·보호 대상 검사는 약화시키지 않았습니다.
이를 새 버튼·선택 메뉴·조치에 연결하지 않으며 자동 검열의 위반 메시지 단건 삭제는 계속 작동합니다.

역할 지급/회수, 메시지 고정/해제, 자동 해제 임시 밴, 영속 경고·장기 기록, 금칙어 온라인 편집은 이번 패치에서 제공하지 않습니다.
역할 지급은 허용 목록과 비공개 채널 접근 상승 검증 없이 열 수 없으며, 자동 임시 밴은 영속 상태·기동 복구 설계 없이 제공하지 않습니다.
기존 금칙어 조회·탐지 테스트는 계속 사용할 수 있습니다.

## 슬래시 명령 게시·노출 진단

의도한 명령은 `/시작`, `/질문`, `/그림`, `/내정보`, `/관리` 정확히 다섯 개입니다. `/질문`만 AI 질문 명령이며 `/ai질문`을 새로 등록하지 않습니다.
일반 회원은 앞 네 개를 사용합니다. `/관리`가 선택기에 보이더라도 실제 패널은 서버 측 ID 인증 후 비공개로만 전송됩니다.
`/관리`의 `guild_only`는 DM 실행 금지이며 전역 등록과 모순되지 않습니다. 기본 Administrator 권한으로 파딱의 선택 자체를 막지 않습니다.
전송 메타데이터는 다섯 개 모두 `default_member_permissions=null`, `integration_types=[0]`입니다.
일반 명령의 `contexts=[0,1]`, `/관리`는 `[0]`이며, 연령 제한을 사용하지 않습니다. `default_member_permissions=0`은 일반 회원 개방이 아닙니다.
서버 설치를 명시하고 일반 명령의 기존 봇 DM 사용만 보존하며 사용자 설치/다른 개인 채널 기능은 새로 열지 않습니다.

| 시작 모드 | 원격 읽기 | 원격 쓰기 | 운영 절차 |
| --- | --- | --- | --- |
| `auto` | 전역 목록·권한·실행/설치 범위·연령 제한·별칭 확인 | 누락·구형 별칭·잘못된 접근 메타데이터가 있을 때만 | 기본·권장. 안전한 상태면 `already_published`로 종료 |
| `0` | 같은 진단 수행 | 없음 | 변경 없이 원인을 조사할 때. 누락 명령을 복구하지 않음 |
| `1` | 기존 원격 범위 검증 | 검증 통과 후 전역 게시 | 의도한 강제 복구 배포에서만 사용; 이후 `auto`로 복원 |

전역 bulk sync 전에 로컬 명령과 원격 명령이 의도한 앱·범위인지 확인합니다. 예상 밖 확장 명령·다른 타입 명령이 있으면 게시를 중단합니다.
원격 조회 실패·앱 ID와 봇 ID 불일치 역시 게시를 중단합니다. 다른 명령 전체 삭제로 해결하지 않습니다.
자신의 구형 `/ai질문`만 정리하며 길드 전용 별칭은 길드별로 별도 확인합니다. 전역 sync만으로 길드 별칭이 없어지는 것은 아닙니다.
길드의 동명 명령도 별도 집계합니다. 전역 감사가 정상이고 모드가 `auto`/`1`이면 이 앱의 의도한 다섯 명령에 남은 기본 권한만 `null`로 개별 복구합니다.
동명 명령을 삭제하거나 guild bulk sync하지 않으므로 ID·옵션·명령별 연동 설정은 보존합니다. 다른 앱/다른 이름/다른 명령 타입은 수정하지 않습니다.
길드 기본 권한 복구의 실패는 코드와 개수로 표시하며 다른 명령의 진단을 계속합니다. 길드 명령의 오래된 옵션·연령 제한 등은 자동 변경하지 않습니다.
기동 중 한 번 감사하고 재연결 `on_ready`마다 전역 sync를 반복하지 않습니다.

접근 실패는 아래 순서로 분리합니다.

1. **게시:** `event=slash_registered count=5`는 로컬 등록입니다. `slash_visibility_audit`의 누락·권한 제한·구형 별칭·예상 밖 개수를 확인하고 `slash_sync_success` 또는 `already_published`를 확인합니다.
2. **앱/Discord 권한:** Developer Portal의 Application ID와 시작 로그의 앱/봇 ID, 올바른 서버 설치와 `applications.commands` 범위를 확인합니다. 서버 설정 → 연동/Integrations → 도리봇 → 명령에서 사용자·역할·채널 제한, 현재 채널의 애플리케이션 명령 사용 권한을 점검합니다.
3. **설정:** Northflank의 실제 런타임에 두 ID가 적용되고 재시작됐는지 확인합니다. `admin_configuration`의 유효성·등록 개수·서버 범위·사유 코드만 확인하며 비밀값을 덤프하지 않습니다.
4. **서버 인증/실행:** `event=admin_open result=allowed|denied reason=...`와 하위 실행 결과를 확인합니다. 인증 성공 후의 봇 권한 부족·보호 대상·역할 우위 실패를 명령 표시 문제와 구분합니다.

길드 연동의 개별 사용자/역할 권한은 전역 sync로 강제 해제할 수 없습니다. 운영자가 명령별로 수정하고 일반 네 명령을 함께 숨기지 않도록 확인합니다.
봇 토큰으로 연동 권한을 변경할 수 없습니다. 이 작업은 별도 사용자 OAuth 권한 흐름을 추가하거나 서버 역할/채널 권한을 자동으로 풀지 않습니다.
공식 기준: [명령 권한·앱 전체 설정과 명령별 설정](https://docs.discord.com/developers/interactions/application-commands#permissions).
`/관리`를 일반 텍스트로 보냈다면 실제 slash interaction이 아닙니다. 클라이언트 `/` 선택기에서 도리봇의 명령을 새로 선택하세요.
일반 네 명령도 정확한 `/명령이름`을 일반 메시지로 보내면 실행하지 않고 하루 한 번 선택기·`!명령진단` 안내만 합니다.
`This command is outdated`는 서버/클라이언트 선택기 단계의 오류일 수 있습니다. 한 replica와 배포 버전, 원격 결과를 확인한 뒤 클라이언트 재시작·전파를 확인하고 무작정 삭제/재생성을 반복하지 않습니다.

### 일반 회원·일반 역할 파딱의 접근 복구

2026-10-24 지정된 아사모 5개·삼사모 7개 채널 전체의 역할·회원 우선 설정을 점검했습니다.

   본인·서버별 60초 제한이며 현재 채널에 90초 후 삭제되는 응답을 보냅니다. 원문·닉네임·환경변수 값은 표시하지 않습니다.

2. 진단에서 **내 애플리케이션 명령어 사용: 거부**이면 서버 역할·카테고리·채널의 유효한 `Use Application Commands`를 확인합니다.

## 기존 공용 record-channel 하나의 삭제 기록

서버별 기존 `LOG_ROUTES`와 `CHANNEL_TO_LOG`를 그대로 사용합니다. 별도 비공개 삭제 채널을 만들거나 새 목적지 ID를 요구하지 않습니다.
일반 수동 삭제, 신규 메시지 검열, 수정 후 위반 삭제, 보조 재점검의 위반 단건 삭제가 같은 기존 공용 기록 채널로 갑니다.
`MOD_LOG_CHANNEL_ID`는 관리 조치 메타데이터 옵션이며 삭제 원문 목적지를 바꾸지 않습니다.

명시적으로 `LOG_ROUTES`에 등록한 원본 전체는 기본 `REGISTERED_SOURCE_CONTENT=1`에서 **확보된 삭제 원문·실측 탐지 문자열·미디어 상세**를 공용 기록에 표시합니다.
비공개·독자 범위 미확인도 포함합니다. 이는 2026-10-23 운영자가 승인한 재게시 범위이며 채널 권한을 새로 열지는 않습니다.
작성자·채널의 실제 멘션과 KST를 유지하고 확보하지 못한 원문/작성자는 확인 불가로 표시합니다. 외부 삭제의 실행자는 추측하지 않습니다.
메시지 ID 등 숫자 라벨은 카드에서 생략하며 내부 스냅샷·중복 방지에는 보존합니다.
공용 기록 열람자와 Discord 내 보관 기간·삭제 담당자는 운영자가 관리합니다.

원문 공개 판정 우선순위는 다음과 같습니다.

1. `DELETION_PUBLIC_LOG_INCLUDE_CONTENT=0`이면 어떤 승인도 콘텐츠 비공개를 우회하지 않습니다.
2. `DELETION_PUBLIC_LOG_REGISTERED_SOURCE_CONTENT=1`이면 기존 명시 원본 전체가 승인 대상입니다. 개별 ID 목록은 필요 없습니다.
3. 전체 명시 원본 승인을 `0`으로 끄면 V8 방식으로 돌아갑니다. 독자 범위 검증을 통과하거나
   `DELETION_PUBLIC_LOG_PRIVATE_FULL_SOURCE_IDS`에 선택 등록한 명시 원본만 상세 공개하며 나머지 명시 비공개 원본은 기본 메타데이터만 남습니다.
4. 명시되지 않은 자동/추가 원본은 언제나 독자 범위 검증을 요구합니다. 미등록 비공개·권한 불명 원본은 카드 자체를 보내지 않습니다.

승인은 원본/목적지 ID·서버 일치·채널 종류·봇 송신 권한 검증을 생략하지 않습니다.
원본 채널 캐시가 없어도 신뢰할 수 있는 현재 메시지 스냅샷이 있으면 명시 승인 원문을 표시할 수 있습니다.
스냅샷 자체가 없으면 원문을 만들지 않고 **확인 불가(캐시/스냅샷 없음)**로 표시합니다. 검열 삭제는 로그와 독립적으로 계속 수행됩니다.

`DELETION_LOG_ALL_GUILD_CHANNELS=1`은 같은 서버에 기존 목적지가 하나로 확인될 때만 새 원본 후보를 포함합니다.
`0`이면 기존 매핑과 선택적 추가 원본 ID만 대상으로 합니다. 추가 ID는 명시 `LOG_ROUTES`가 아니므로 같은 공개 범위 검사를 통과해야 합니다.
자동/추가 감시한 미등록 비공개·권한 불명 채널은 기본 기록도 공용으로 보내지 않으며 `private_unrouted_skipped` 또는 `unverified_unrouted_skipped`로 분류합니다.
DM·다른 서버·미지원 채널·목적지 자신·일반 봇 메시지는 제외합니다. 현재 공용 기록의 원본은 일반 텍스트 채널이며 스레드 원문은 자동 복제하지 않습니다.

운영 상태에서 목적지 식별 여부, 봇의 View Channel/Send Messages/Embed Links, 감시·제외 집계, 최근 성공 시각과 실패 사유를 확인합니다.
`sent_full`은 실제 상세 본문 전송이며, 기본 기록과 원문 미확보는 `sent_metadata_only`입니다. `failed`·`skipped`·인공 전송 테스트는 별도로 확인합니다.
익명 카드와 `sent_restricted` 전송 결과는 V8에서 중단됐으며 남아 있는 같은 이름의 카운터는 호환용입니다.
`/관리 → 삭제 로그 전송 테스트`는 **실제 사용자 원문 없는 테스트 카드 한 장**을 기존 목적지로 보내고 비공개 결과를 반환합니다.

| --- | --- |
| 기존 채널 ID | 서버별 `LOG_ROUTES`가 실제 기존 record-channel을 가리키는지 대조. 사용자 ID와 혼동 금지 |

카드는 **User·Channel 실제 멘션 → Deleted Content → 사유 한 곳 → 존재하는 미디어 → 서버명·KST 푸터** 순서로 표시합니다.
중복 영문/한글 라벨·반복 ID·빈 첨부 개수·정상 공개 상태의 정책 경고를 줄입니다. 수정/과거 검열 문맥은 해당 사건에서만 유지합니다.
실측 탐지 규칙·사유, 실제 이모지·스티커·파일명/MIME/크기/종류·스포일러 등의 확보 가능한 메타데이터는 보존합니다.
`시321133발`은 원문 그대로 표시하며 정규화 결과로 치환하지 않습니다. 일반 삭제의 실행자를 추측하지 않고 캐시 미스의 원문을 만들어내지 않습니다.
텍스트 없이 첨부만 있는 경우의 원문 없음과 최신 스냅샷 부재의 확인 불가를 구분합니다. 길이/항목 상한에 도달하면 생략을 명시합니다.
`AllowedMentions.none()`·멘션/Markdown/기만 링크/제어문자 처리와 Embed 한도를 적용합니다.
첨부 바이트를 자동 다운로드·재업로드하지 않고 URL·프록시·썸네일의 영구 열람을 보장하지 않습니다.

삭제 전 스냅샷과 일반/raw/bulk 이벤트는 같은 파이프라인을 사용합니다. HTTP/Gateway 순서가 역전되어도 중복을 억제하고 삭제 실패를 성공으로 기록하지 않습니다.
스냅샷·전송 예약·중복 기록에는 메모리 상한과 TTL이 있습니다. 재시작·오프라인·캐시 미스·폭주 상한·REST 실패 구간의 누락 가능성은 남습니다.
삭제 시각은 봇의 확인 시각이며 Discord 내부의 정확한 삭제 시각으로 표현하지 않습니다. 알 수 없는 원문·작성 시각·첨부 내용은 복원하지 않습니다.
Northflank stdout, 예외 텔레메트리, 관리 링버퍼, Pickle/JSON에 삭제 원문·첨부 URL·프롬프트·API 키를 남기지 않습니다.

## 수정 즉시 검열과 72시간 보조 재점검

`on_raw_message_edit`가 주 경로이며 캐시된 `on_message_edit`와 같은 순수 판정·단건 삭제 경로를 공유합니다.
`1`을 금칙어로 수정하거나 `ㅇ`을 `https://naver.com`으로 수정하면 72시간을 기다리지 않고 이벤트 수신 후 재검열합니다. 현재 원문·수정 시각을 사용하고 이전 본문을 현재 원문으로 재사용하지 않습니다.
부분 raw payload의 `content` 부재를 빈 문자열로 보지 않으며 필요한 현재 상태는 제한된 API 재조회로 확인합니다.
일반 embed-only 갱신은 제외하되 HTTP(S) 링크 미리보기가 도착한 경우 현재 본문을 조회합니다. 미리보기 URL 자체를 원문으로 간주하거나 그것만으로 삭제하지 않습니다.
신규/수정 메시지는 기존 링크 허용·금칙어 면제 채널·면제권 정책을 공유합니다. 같은 수정의 중복 이벤트가 면제권·삭제·카드를 반복 처리하지 않도록 기록합니다.
HTTP(S), `www` 주소, Discord 초대 링크와 기존 지정 도메인은 신규/수정/재검사/질문에서 같은 링크 규칙을 사용합니다.
수정·스캔 경로는 XP·업적·VIP·AI·타이핑·임시 경고를 새로 실행하지 않습니다.

즉시 검열에서 본문을 이미 수신했다면 View Channel·Manage Messages가 필요합니다. 현재 본문 재조회와 과거 기록 스캔에는 Read Message History도 필요합니다.
본문 없이 조회 권한도 없으면 `history_forbidden`으로 제외하며 이전 본문이나 미리보기로 내용을 추측하지 않습니다.
배포 후 링크 차단 대상 채널에서 활성 면제권이 없는 계정으로 `ㅇ → https://naver.com`을 확인합니다.
삭제되지 않으면 `EDIT_MODERATION_ENABLED=1`, Message Content Intent, 실제 채널 권한, 허용 채널/상위 채널 및 면제권을 구분해 점검합니다.

시작 시 READY를 기다린 단일 스케줄러가 기본 45초 유예 후 검사하고 이후 기본 72시간 간격으로 실행합니다. 재연결마다 새 작업을 만들지 않습니다.
우선 최근 48시간을 검사한 뒤 96~48시간의 나머지 구간도 검사합니다. **72시간마다 48시간만 검사하는 24시간 공백 정책은 사용하지 않습니다.**
현재 설정에서 조회 범위가 간격+24시간보다 작으면 경고하고 확장합니다. 검사 범위를 짧게 설정해 모든 기간을 검사했다고 해석하지 마세요.

조회는 **수정 시각이 아닌 메시지 생성 시각** 기준입니다. 온라인이면 수개월 전 메시지 수정도 raw 이벤트로 처리할 수 있지만,
오프라인 중 수정된 생성 96시간 밖의 글은 별도 영속 인덱스 없이 탐지를 보장할 수 없습니다. 장기 오프라인·캐시 미스·인텐트/권한 누락도 완전 탐지 대상이 아닙니다.
채널당 2000개·전체 20000개 기본 상한에 도달하면 96시간 전체를 확인한 것이 아니며 운영 상태의 부분 검사 집계를 확인해야 합니다.

봇의 View Channel·Read Message History·Manage Messages를 확인합니다. 미지원/기록 채널·봇·DM을 제외하고 비동기 페이지 조회·작은 동시성·협력적 yield로 평소 응답을 보호합니다.
스캔은 면제권을 소비하지 않으며 이력에서 면제를 재구성할 수 없는 미수정 위반 글은 보수적으로 제외합니다. 실제 수정 후보도 현재 면제·기록된 처리 결과를 존중합니다.
위반이 확인되어도 해당 메시지 한 건만 삭제하며 특정 사용자의 정상 과거 글 전체 정리로 확대하지 않습니다.

`/관리 → 수정 메시지 검열`은 읽기 전용입니다. 활성 상태, 간격/범위, 마지막 완료, 검사·수정·위반·삭제 수, 부분·제외·권한/오류 집계를 확인합니다.
이는 전체 채널 원문 열람 도구가 아니며 숨김 채널명·새 채널 목록을 제공하지 않습니다. 스캔 상태·진행·중복/면제 기록은 재시작 시 초기화됩니다.

## XP·타이핑·AI 회귀 정책

활동 XP만 등급을 판단합니다. 총 표시 XP는 `activity_xp + bonus_xp + legacy_xp`이고 업적 보너스는 다음 등급을 재귀 지급하지 않습니다.
월~목 적격 메시지 +25, 금~일 +45, XP 쿨다운 5초, 전설 기준 활동 450이므로 평일 18회/금~일 10회가 최소입니다.
첫 1/2/3회 적격 메시지로 전설이 되면 배포를 중단합니다. VIP 축하는 사용자·날짜별 1회이며 하루 전체 한 명 정책이 아닙니다.
기존 점수·수령·효과·업적 이력은 호환 보존하며 근거 없는 점수 역산·전 사용자 초기화를 하지 않습니다.
오류가 있는 오늘의 데이터 정리가 필요하면 봇 중지·외부 백업·특정 ID의 사본 검토·운영자 선택·원자적 저장 순서를 따릅니다. 자동 정리 명령은 없습니다.

타이핑은 첫 이벤트의 1.3초 타이머를 한 번만 예약하며 뒤이은 타이핑으로 연장하지 않습니다. 같은 채널의 다른 사용자를 차단하는 전체 쿨다운이 없습니다.
성공 전송 시 사용자×서버별 24시간 제한을 확정합니다. 같은 서버의 채널/스레드는 공유하고 다른 서버는 독립적입니다.
전송 실패는 24시간 제한을 소비하지 않으며 작성 완료의 취소/보조 안내 정책을 유지합니다. 검열·명령·봇·DM은 보조 안내 대상이 아닙니다.
구형 `user:<id>` 상태는 기존 24시간이 만료될 때까지 보수적으로 적용하고 신규 기록은 서버별 키로 저장합니다.
컨테이너 하나 안에 실제 프로필 멘션 인사 → 도움말 → 구분선 → 제목 → 버튼 2×2와 행 사이 Separator를 유지합니다.
검증된 계정 ID만 멘션으로 만들며 AllowedMentions.none()으로 알림은 차단합니다. ID가 없으면 안전한 표시이름을 사용합니다.
`ui:question`, `ui:image`, `ui:growth`, `ui:menu`와 영속 버튼을 보존합니다. 내부 1.3초 대기는 Gateway/REST를 포함한 절대 완료 보증이 아닙니다.

기존 공용 Gemini 답변·Horde 그림·접두사 명령·검열·무료 한도 보호를 별도 회귀 확인합니다.
질문 공개 안내와 멘션 억제, 429·인증·타임아웃·안전 차단 오류, 단일 질문/단일 답변을 확인하며 자동 제공자 전환이나 결제 상태 변경을 하지 않습니다.

## 실제 Discord 수용 검사

아래는 운영자가 시험 서버와 실제 계정으로 수행할 목록입니다. 로컬 모의 테스트 통과가 이 목록의 완료를 의미하지 않습니다.
테스트 조치의 대상은 사전에 정한 낮은 역할의 시험 계정이며 실제 회원에 대한 의도치 않은 조치를 피합니다.

1. 일반 역할인 `491239880005910538`이 선택기에서 `/관리`를 실행하고 비공개 패널을 엽니다.
2. 일반 역할인 `855749166764654653`과 서버 소유자도 패널을 엽니다. 관리자 역할은 새로 지급하지 않습니다.
3. 일반 제3자·Discord 관리자 역할만 있는 제3자·DM·설정 범위 밖 계정은 거부됩니다. 버튼/메뉴/모달 변조도 거부됩니다.
4. 파딱보다 역할이 높지만 봇보다 낮은 시험 계정에 타임아웃→해제·별명 변경→초기화·필요한 시험 제재를 실행합니다.
5. 봇의 해당 권한을 일시 제거하거나 대상 역할을 봇과 동급으로 바꾸면 확인 이후 실행도 무부작용 실패합니다. 권한은 시험 후 복구합니다.
6. 숨김 채널을 볼 수 없는 파딱에게 채널 목록·본문·관리 UI가 새로 노출되지 않습니다. 현재 채널 확인창을 다른 채널로 옮겨도 실패합니다.
7. 일반 회원이 `/시작`, `/질문`, `/그림`, `/내정보`를 실제 사용합니다. `/질문`은 모달·요청·답변 각각 한 번이며 `/ai질문` 별칭은 남지 않습니다.
8. 공개 원본 일반 메시지 삭제가 기존 record-channel 한 곳에 작성자·채널 프로필/채널 링크, 원문과 시각으로 표시됩니다. 알 수 없는 삭제 주체는 추측하지 않습니다.
9. 공개 시험 채널의 `시321133발` 자동 검열 카드에 원문 숫자가 그대로 남고 실제 일치 규칙과 구분됩니다. 숫자 ID 라벨은 없으며 내부 중복 방지는 유지됩니다.
10. 이모지·정적/애니메이션 커스텀 이모지·스티커·이미지·영상·문서·스포일러·첨부만 전송·raw bulk에서 메타데이터와 누락 표기가 정확합니다.
11. 명시 `LOG_ROUTES` 비공개 원본(예: `moderator-only`)의 삭제 원문을 일반 계정도 기존 공용 기록에서 확인합니다. 카드가 User·Channel→Deleted Content→사유→존재하는 미디어→서버·KST 순서인지 확인합니다. `REGISTERED_SOURCE_CONTENT=0`으로 V8 복귀, `INCLUDE_CONTENT=0`으로 전역 가림도 시험 후 복원합니다. 미등록 비공개 원본은 카드가 없어야 하며 합성 전송 테스트는 사용자 원문 없이 한 장만 갑니다.
12. 같은 채널의 두 사람이 연속 타이핑하면 각자 안내를 받고 동일 사용자/서버는 24시간 제한됩니다. 다른 서버·전송 실패 복구·모바일 2×2·재시작 버튼을 확인합니다.
13. 정상 글 `1`을 `시발`, 링크, 금칙어+링크, 숫자/공백 우회 입력으로 수정하면 즉시 재검열되고 수정 원문·사유가 같은 기록 채널에 한 번만 갑니다.
14. 가상 시계로 72시간 주기·96시간 범위와 48시간 우선+나머지 구간을 검증합니다. 3000개 이상 이력·전체 상한·API 실패·취소 때 부분/오류 진단을 확인합니다.
15. 오래된 캐시 미스 수정·raw/cached 역순·삭제 이벤트 역전에서 삭제/카드 중복이 없습니다. 면제권은 동일 수정에 한 번, 스캔에는 소비되지 않고 XP·경고도 바뀌지 않습니다.
16. 새 사용자 조치 Select에 cleanup 항목이 없고 오래된 cleanup 선택은 비공개 거부됩니다. 내부 서비스·모달·검증·기존 삭제 테스트 코드는 보존됩니다.
17. 평일 첫 1/2/3회 적격 입력은 전설이 아니며 18회/금~일 10회에 전설과 사용자별 VIP 1회가 됩니다. 여러 사용자·날짜 경계·중복 수령도 확인합니다.
18. 쓰기 잠금/상속 해제 시 다른 overwrite는 유지됩니다. 별도 쓰기 Allow 역할의 예외를 확인하고 해제가 이전 상태 복원이 아님을 안내합니다.
19. 서버별 임시 경고 조회가 섞이지 않고 제3자 조회는 거부됩니다. 재시작하면 경고·최근 기록·확인은 초기화되고 Discord timeout·별명·채널 상태는 유지됩니다.
20. 로그 목적지의 View Channel/Send Messages/Embed Links를 각각 제거한 경우 실패 이유를 구분하고 원래 검열은 계속되는지 확인합니다. stdout·영속 파일에 원문/URL/비밀값이 없어야 합니다.

게시 성공 후 클라이언트 표시·모바일 폭·Discord 연동 설정·실제 토큰의 앱 일치·Message Content Intent·원격 API 속도와 레이트리밋은 별도 실서비스 검증 사항입니다.
Python 3.13, 실제 Northflank 볼륨·배포 이미지와 72시간 운영 주기의 지속성도 로컬 모의 검증과 구분해 기록합니다.

## 배포·롤백 순서

1. 후보 코드에서 `python -m unittest discover -s tests -v`, `python -m compileall -q .`, `git diff --check`를 수행하고 결과·의존성·런타임을 기록합니다.
2. 위 외부 백업과 환경설정 이름을 확보하고 자동 CD 및 구/신 replica 중복 실행 여부를 확인합니다.
3. 시험 서버에서 수용 검사를 수행한 뒤 후보 커밋을 한 replica로 배포합니다. 환경변수·영속 마운트·앱 ID를 확인합니다.
4. 시작 로그의 관리자 설정·슬래시 감사·원격 게시, READY 후 수정 검열 작업·삭제 테스트를 확인합니다. 이후 기존 AI·XP·타이핑 회귀를 점검합니다.
5. 장애 시 원인별로 송신 경로를 진단합니다. 이전 선택 승인 방식으로 돌아가려면 `DELETION_PUBLIC_LOG_REGISTERED_SOURCE_CONTENT=0`을 설정하고 개별 목록을 점검합니다. 모든 본문을 가리려면 `DELETION_PUBLIC_LOG_INCLUDE_CONTENT=0`, 기록 송신 전체 중지는 `DELETION_PUBLIC_LOG_ENABLED=0`으로 재시작합니다. 목록을 비우는 것만으로 기본 전체 승인이 꺼지지 않으며 이미 게시된 카드는 운영자가 별도 삭제해야 합니다. 검열 전체를 끄거나 파딱에게 Administrator를 주지 않습니다.
6. 롤백은 후보 프로세스를 먼저 중지하고 같은 볼륨을 유지합니다. XP 스키마 호환을 확인한 검증된 커밋만 배포하며 필요하면 검증한 데이터 백업을 원자적으로 복원합니다.
7. 코드 롤백만으로 Discord에 적용한 타임아웃·밴·별명·슬로우모드·쓰기 overwrite가 원복되지는 않습니다. 시험 중 변경한 Discord 상태는 기록한 값과 비교해 운영자가 별도로 복구합니다.
8. 구/신 프로세스의 동시 실행·검증 없는 Pickle 전체 삭제·예상 밖 명령 일괄 삭제를 하지 않습니다. 배포/롤백 커밋과 실제 계정 검증 결과를 남깁니다.
