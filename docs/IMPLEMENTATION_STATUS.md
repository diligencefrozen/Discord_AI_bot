확인은 사용자/서버에 묶인 120초 단일 사용 요청이며 실행 직전 멤버/권한을 다시 조회합니다.
타임아웃은 최대 28일입니다. 일반 채널 슬로우모드는 `manage_channels`, 스레드는 `manage_threads`를 검사합니다.
예외 원문·메시지/프롬프트·별명·사유 본문을 감사 기록에 남기지 않습니다.

## 확인한 원인과 운영 진단의 경계

- XP 원인은 업적 검사에서 `add_xp(record_message=False)`를 다시 호출하는 재귀였습니다.
  보너스가 다음 등급 업적을 열어 두 번째 메시지에 전설까지 도달했습니다.
  이제 첫 1/2/3회로 전설이 될 수 없고 활동 XP 450이 필요합니다.
- 타이핑의 5초 대기·후속 이벤트마다 타이머 취소·채널 전체 60초 제한을 제거했습니다.
  stop-typing 이벤트가 없으므로 작성만 멈추면 첫 타이머를 실행합니다.
  먼저 메시지를 보내면 대기 타이머를 취소하고 적격 일반 메시지만 보조 안내를 보냅니다.
- 관리자 ID 합집합 검사는 기존에도 존재했습니다. 첨부 사진은 `/관리`가 일반 메시지로 전송된 경우입니다.
  실제 장애가 환경변수·앱 설치·권한·게시 중 무엇인지는 운영 로그 없이는 확정할 수 없습니다.
  [운영 문서](NORTHFLANK_OPERATIONS.md)의 네 단계 진단으로 분리합니다.

## 데이터와 지연의 정확한 의미

`xp = activity_xp + bonus_xp + legacy_xp`이고 등급·활동 순위는 활동 XP만 사용합니다.
월~목 25 / 금~일 45 활동 XP, 5초 쿨다운, 전설 450이므로 평일 18회 / 주말 10회가 필요합니다.
일일 상태는 서울 자정에 초기화합니다. 기존 총점은 이전 기록으로 보존하고 새 활동을 0부터 계산합니다.
이행할 수 없는 개별 레코드는 원본을 보존하고 오류 분류만 기록하여 다른 사용자 데이터가 지워지지 않게 합니다.
해당 레코드는 운영자의 복구가 필요합니다. 롤링 `.bak.*`는 영구 이행 스냅샷이 아니므로 배포 전 별도 백업이 필요합니다.

업적 지급 원장은 XP 파일에 먼저, 업적 파일은 다음에 저장합니다.
활동 트랜잭션 내부 저장을 묶어 반복 fsync/백업을 줄였습니다. 활동 지급당 한 쌍의 동기 파일 저장은 남아 있습니다.
VIP 예약은 네트워크 호출 전에 저장하며 실패/응답 불명확 시 자동 재시도하지 않습니다.
예약 직후 프로세스가 중단되면 축하 메시지가 누락될 수 있어 분산 시스템의 완전한 exactly-once 전송을 주장하지 않습니다.

신규 타이핑 기록은 서버×사용자별입니다. 서버 정보 없는 과거 `user:<id>` 기록은 남은 24시간만
모든 서버에 보수적으로 적용하고 만료 후 신규 서버별 기록으로 전환합니다.
파일 저장 잠금은 Discord 전송을 직렬화하지 않습니다. 기본 1.3초는 봇의 대기 시간이며
Gateway 이벤트 도착·발송 완료·이벤트 루프 부하까지 보장하는 SLA가 아닙니다.

## 보존한 기능과 미구현 범위

Gemini 질문·한도·안전성·공개 성공/비공개 오류, 독립 Horde 그림, 기존 검열과 면제권,
접두사 명령, 슬래시 5개, 지속 버튼을 보존했습니다. 외부 DB 없이 기존 PickleStore를 사용합니다.
Discord timeout·서버 별명·밴·슬로우모드는 재시작 후 유지됩니다.
확인·최근 관리 기록은 메모리여서 재시작하면 초기화됩니다.
파일 재배포 보존에는 단일 replica와 영속 DATA_DIR/STATE_DIR가 필요합니다.

채널 잠금/권한 복구, 임시 밴 자동 만료, 역할 지급/제거, 장기 경고 누적,
필터 실시간 편집, 장기 관리 기록은 구현하지 않았습니다. 자동 임시 밴 대신 native timeout을 사용하세요.
운영 상태는 조회용이며 호스팅 영속 볼륨 장착을 코드만으로 증명하지 않습니다.
