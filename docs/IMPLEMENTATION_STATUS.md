# 도리봇 구현·검증 상태

갱신: 2026-10-21 (Asia/Seoul). 기존 인수인계 전체·AI 답변 공개·Gemini/슬래시 핫픽스 및 타이핑 공지 24시간 제한을 반영합니다.

## 타이핑 공지 반복 수정

기존 코드는 12시간과 `서버:채널:사용자` 기준이어서 채널 이동 시 재노출됐습니다.
또한 전송 응답 중 새 타이핑 이벤트가 이전 작업을 취소하면 이미 전송된 공지의 시각 기록이 누락될 수 있었고,
이전 작업의 정리가 대체 작업의 추적 정보를 지우는 경쟁 조건이 있었습니다. 두 취소 경로는 모의 전송으로 재현했으며 실제 운영 전송 로그는 확인하지 않았습니다.

- 사용자별 `user:<id>` 기준으로 마지막 성공 전송부터 24시간을 적용하고 채널/서버 이동도 같은 제한을 공유합니다.
- 구형 채널별·사용자 ID 저장 키를 사용자별 최신 유효 시각으로 합쳐 기존 기록을 유지합니다. 잘못된 개별 값·NaN·무한대는 다른 정상 기록을 지우지 않습니다.
- 최종 제한 확인·전송·시각 기록·원자적 파일 저장을 하나의 잠금 작업에서 수행하고 타이핑 타이머 취소로 중단되지 않도록 보호합니다. 전송 후 기록을 먼저 보존하고 지표를 갱신합니다.
- 이전 작업은 자신의 추적 항목만 정리합니다. 실패한 전송에는 쿨다운을 적용하지 않고 파일 저장 실패 시에도 메모리 제한은 유지합니다.
- 5초 지연·작성 후 공지 취소 조건·60초 채널 제한·컨테이너/버튼은 유지합니다. 재시작 후 제한 보존에는 한 인스턴스와 영속 `DATA_DIR`/`STATE_DIR`가 필요합니다.

## 시간 초과·슬래시 동기화 핫픽스

운영 로그가 제공되지 않았으므로 실제 시간 초과와 Discord 명령 캐시의 근본 원인은 확정하지 않습니다.
코드는 다음 진단·수명주기 보완을 적용했으며 실서비스 장애 해결 여부는 운영 로그로 확인해야 합니다.

- `ai_providers.py`: Gemini 호출 시작/종료의 `event`, `elapsed_ms`, `model`, `result`, 가능한 `http_status`를 구조화 로그로 기록합니다. 시간 초과는 connect/read/write/pool 단계로 구분하며 기존 `GeminiProviderError.code="timeout"`과 인증·404·429·5xx 분류를 유지합니다. 키·프롬프트·응답·토큰·예외 원문은 기록하지 않습니다.
- `.env.example`, README와 운영 가이드: `GEMINI_TIMEOUT_SECONDS=60`을 임시 운영 완화값으로 권장합니다. 코드의 미설정 기본값은 30초이며 비정상 숫자 검증을 유지합니다. httpx 단계별 제한이므로 전체 요청 절대 시간 제한이나 원인 해결 보장이 아닙니다.
- `main.py`: `Doribot.setup_hook`에서 로컬 다섯 슬래시 명령과 지속 버튼을 등록합니다. `SLASH_SYNC_ON_STARTUP=1`로 명시한 시작에서만 전역 명령을 동기화하며 미설정/`0`은 로컬 등록만 합니다. `on_ready` 재연결은 동기화를 수행하지 않습니다. 첫 설치·명령 변경 배포는 한 번 `1`로 게시한 뒤 일반 실행은 `0`으로 관리해야 합니다.
- `bot_ui.py`: 등록·동기화를 하나의 잠금으로 보호하고, 자체 명령 객체를 재사용해 부분 등록 실패 후 중복 없이 재개합니다. 외부 명령 이름 충돌은 사전 거부합니다. 명령이 정확히 다섯 개인지 확인한 뒤 전역 동기화하며 명령 삭제·길드 복사·이중 범위 등록은 하지 않습니다.
- 동기화 성공은 Discord가 반환한 이름/개수와 앱·봇 ID를 기록합니다. 실패는 예외 종류/상태만 기록하고 자동 재연결 반복 재시도는 없습니다. `/관리`의 `guild_only`와 모든 파딱 서버 측 접근 검사는 그대로 유지합니다.
- Gemini 질문의 즉시 비공개 defer, 성공 답변 공개, 실패 비공개, 단일 요청·기존 예산 보호, Horde 이미지 독립성과 DB 없는 영속화를 회귀 검증했습니다. `/관리 outdated`는 Discord 클라이언트 단계의 메시지로 봇에서 가로채거나 즉시 해결을 보장할 수 없습니다.

실운영에서는 [핫픽스 설정·진단 절차](NORTHFLANK_OPERATIONS.md)를 따라 한 replica, 앱/봇 ID,
동기화 로그를 확인하고 Discord 클라이언트 재실행·명령 재선택·전파 대기를 진행합니다.

## 보존한 기능과 정책

- 기존 XP/레벨/업적 보상, `daily_xp_data.pkl`, `achievements_data.pkl`, 원자적 저장·백업 복구.
- 금칙어/링크 예외 채널과 면제권 공동 효력. 위반 메시지/프롬프트당 최대 1회 소모, 정상 허용 시 소모 없음, 시간제 `all`·`trial` 횟수 유지.
- `!ask`·`!img` 및 나머지 접두사 명령, 기존 슬래시 명령과 `ui:*`/`admin:*` 버튼 식별자.
- 타이핑 감지 지연 5초·전송 조건·사용자별 24시간 쿨다운·채널 쿨다운, 기존/신규 공지의 지속 콜백 등록.
- 이미지 크기·검증·Horde 설정·동시 생성 제한·사용자 쿨다운·성공 결과 공개와 비공개 완료 확인.
- 내 성장·전체 메뉴·파딱 패널·활성 목록·탐지 테스트·인터랙션 오류는 비공개.

`!ask`의 오류는 Discord 접두사 명령이 ephemeral을 지원하지 않아 기존처럼 채널에 안전한 문구로 표시합니다.
AI 질문의 성공 결과는 모든 경로에서 공개이며 질문 원문은 봇이 별도 재게시하지 않습니다.

## 파딱과 실제 활성 목록

기본 정책의 원문 99개를 그대로 유지합니다. 정확히 같은 문자열만 중복 제거하고
`fuck`, `Fuck`, `FUCK`는 표시/개수에서 각각 보존합니다. 매칭은 정규화 동등성을 공유합니다.
관리 화면은 실제 `moderation_rules.BAD_ROOTS`에서 계산하므로 페이지 전체 항목 수와 `N`이 일치합니다.

배포 변수에는 기존 `855749166764654653`와 신규 `491239880005910538`를 모두 넣어야 합니다.
단일/복수 ID 합집합·중복 제거·잘못된 값 전체 거부·미설정 소유자 전용·DM 거부·역할 비인가·서버 범위를 검사합니다.
소유자의 기존 접근은 유지합니다. 모든 관리 진입/클릭/모달/페이지 이동에 서버 측 검사가 있습니다.

## 로컬 검증

- 번들 Python 3.12.14에 전체 requirements를 작업용 `.venv-deps`로 설치했습니다. discord.py 2.7.1/httpx/Pillow 실제 의존성을 사용합니다.
- 가짜 Discord 토큰, dotenv 비활성화, 임시 데이터 디렉터리로 `main.py` import 및 Bot 생성 성공. 외부 로그인/네트워크 호출은 하지 않았습니다.
- 실제 라이브러리로 구형/Components V2 View의 persistent 등록과 5개 슬래시 명령(시작/질문/그림/내정보/관리) 등록 성공.
- 최종 `python -m unittest discover -s tests -v`: **134개 통과, 실패 0, 건너뜀 0** (4.850초). 번들 Python에 `PYTHONPATH=.venv-deps`를 적용해 실행했습니다.
- 제공자 25개, UI 25개, 검열 규칙 17개, 메인 서비스 18개, 슬래시 상태/트리 12개, 실제 시작/재연결 라이프사이클 7개, 타이핑 제한/취소/영속화 19개 및 기존 저장/삭제/지표 11개를 포함합니다. 모의 HTTP 결과는 실제 Gemini/Horde 생성 품질 검증으로 간주하지 않습니다.
- 실제 의존성으로 `main.py` 전체를 격리 로딩하고 새 `setup_hook`의 다섯 명령·지속 버튼 등록과 원격 동기화 0회를 확인했습니다. 토큰 없는 AST 기반 테스트도 최초 등록·실패 후 명시적 재시도·동시 호출·재연결·재시작·부분/중복 등록을 검사합니다.
- `py_compile` 및 `git diff --check` 통과. Git의 CRLF 변환 안내는 공백 오류가 아닙니다.
