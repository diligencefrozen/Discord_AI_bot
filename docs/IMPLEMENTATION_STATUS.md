## 7) cleanup 보존과 실시간/주기 검열

`AdminMemberActionsView` Select options에 cleanup은 0개입니다. 구형/위조 Select 값은
`select_action` 앞단에서 비공개 거부합니다. 아래 코드를 제거·no-op 치환하지 않았습니다.

```text
ACTION_LABELS['cleanup']       PERMISSIONS['cleanup']
AdminRequest.preview          AdminService._validate
AdminService.execute          AdminActionModal
select_action의 기존 분기     ADMIN_SERVICE.delete_service 바인딩
```

보존 서비스의 성공/실패/권한·삭제 감사 통합 테스트와 메뉴 비노출/구형 거부 테스트를 함께 유지합니다.

raw edit는 명시된 현재 본문/수정 시각을 사용하며 불완전하거나 시각이 불명확하면 현재 메시지를 재조회합니다.
조회 동시2개·timeout8초, 임베드만 갱신되면 제외합니다. 원장은 ID·시각·본문 SHA-256·결과만
7일/최대8,192개 메모리로 보존하며 동일 수정본은 면제권/삭제를 한 번만 처리합니다.
`나쁜A(면제) → 정상B → 나쁜A(새 시각)`는 새로 판단하고 예전 면제를 재사용하지 않습니다.
오래된 이벤트가 최신 정상본을 삭제하거나 최신 감사 원문을 이전 원문으로 바꾸지 않도록 방어합니다.

별도 단일 작업이 READY 후45초에 시작해 72시간마다 생성 후96시간을 검사합니다.
최근48시간 전체 채널 우선 → 48~96시간, 경계1ms 겹침/ID 중복 제거,
채널2,000개·전체20,000개·기본 동시성1·협력 yield·부분 검사 집계를 구현했습니다.
72/48 설정은 공백 경고 후 주기+24시간 이상으로 보정합니다.
스캔은 면제권을 소비하지 않고 과거 미수정 예외 불명/현재 면제권은 보수적으로 보존합니다.
XP·AI·타이핑·스팸 경고를 재실행하지 않습니다. 재연결 단일 작업과 종료 취소도 검증했습니다.

한계: 조회는 생성 시각 기준입니다. 온라인의 오래된 수정은 raw로 처리하지만 오프라인 동안 수정된
생성96시간 밖 메시지, 한도/권한/캐시 밖 누락은 완전 복구할 수 없습니다.
재시작하면 스케줄·원장이 초기화됩니다. 중단과 완료를 구분하며 장기 exactly-once를 주장하지 않습니다.
