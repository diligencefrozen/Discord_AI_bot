# 삭제 원문 공개와 간결한 카드 — 2026-10-23 KST

## 요청과 적용 범위

운영자는 실제 `moderator-only` 삭제 카드의 본문이 생략되는 것을 확인한 뒤 삭제 원문을 일반 회원도 볼 수 있게 하고,
중복 정보가 많은 UI를 간결하게 바꾸도록 요청했습니다. 공개 범위를 묻는 질문에는 **“기존 LOG_ROUTES에 등록된 모든 원본 채널”**이라고 답했습니다.
이 요청을 기준으로 V8의 명시 비공개 원본 본문 기본 생략·개별 승인 기본 정책을 변경합니다.

작업 시작 코드는 로컬 `develop`의 `7019da0`입니다. 기존 `main.py`의 목적지 네 곳과 원본 매핑을 보존하며,
새 공개 채널 생성·역할/채널 권한 변경·원본 파일 다운로드를 하지 않습니다.

## 공개 결정표

`DELETION_PUBLIC_LOG_ENABLED=1`, `DELETION_PUBLIC_LOG_INCLUDE_CONTENT=1`인 경우입니다.

| 원본과 설정 | 공용 기록 결과 |
| --- | --- |
| 기존 명시 `LOG_ROUTES`, `REGISTERED_SOURCE_CONTENT=1` 기본 | 공개·비공개·독자 범위 미확인에도 확보된 원문·실측 탐지 문자열·미디어 상세 표시 |
| 기존 명시 원본, 원본 채널 캐시 없음·신뢰할 수 있는 스냅샷 있음 | 검증된 사건 정보와 확보된 원문 표시. 서버/ID 불일치 등은 여전히 거부 |
| 기존 명시 원본, 캐시/스냅샷 없음 | ID 등 알려진 정보와 **확인 불가(캐시/스냅샷 없음)**. 원문을 지어내지 않음 |
| 자동 감시 또는 추가 ID만 등록, 독자 범위 검증 통과 | 확보된 상세 카드 |
| 자동 감시 또는 추가 ID만 등록, 비공개·독자 범위 미확인 | 카드 자체를 전송하지 않음 |
| `REGISTERED_SOURCE_CONTENT=0` 또는 잘못된 값 | V8 선택 승인으로 복귀. 독자 범위 검증 또는 개별 `PRIVATE_FULL_SOURCE_IDS` 승인이 없으면 명시 비공개 원본은 기본 메타데이터만 표시 |
| 전역 `INCLUDE_CONTENT=0` | 전체/개별 승인과 무관하게 모든 원문·실제 탐지 문자열·파일명 등 콘텐츠 가림 |
| DM·다른 서버·ID 불일치·미지원 채널·목적지 자신 | 제외. 전체/개별 승인으로 우회하지 않음 |
| 목적지 없음·봇 송신 권한 없음·API 실패 | 실패 코드로 진단. 검열 삭제 자체는 유지 |

“명시 등록”은 코드의 `LOG_ROUTES`/서비스 `routes`에 직접 매핑된 원본을 뜻합니다.
`DELETION_LOG_ALL_GUILD_CHANNELS=1` 또는 `DELETION_LOG_EXTRA_SOURCE_CHANNEL_IDS`만으로는 비공개 본문 공개 승인이 생기지 않습니다.
기존 매핑의 목적지 자신 항목도 재귀 방지 때문에 전송하지 않습니다.

## 카드 구성

단일 빨간 강조선 Embed를 유지하고 정보가 읽히는 순서를 정리합니다. 아래는 구조 예시이며 실제 삭제 사건의 확보된 항목만 표시합니다.

```text
🗑️ 메시지 삭제 기록
Apple Watch · #moderator-only

삭제된 원문
시321133발

사유
자동 검열 · 금칙어 · 일치: 시발

[미디어가 있을 때만 종류·이름·크기 등 표시]

메시지 ID · 사용자 ID · 채널 ID · 서버 · 삭제 확인 KST
```

중복 영문/한글 라벨, 여러 위치의 같은 ID, 매번 나타나는 정책/상태 경고와 `첨부파일 0개`는 줄입니다.
삭제 원문과 탐지용 정규화 문자열은 별개이며 실제 입력 `시321133발`을 그대로 읽을 수 있어야 합니다.
새 메시지는 불필요한 “새 메시지” 문맥을 반복하지 않고 수정·과거 재검사는 필요한 문맥을 남깁니다.
Unicode 이모지는 원문에 보존하며 커스텀 이모지·스티커·첨부·임베드는 확보된 경우만 추가합니다.
원문이 실제로 빈 경우와 확인 불가, 길이/항목 절삭은 계속 구분합니다.

멘션 알림 금지, Markdown/코드블록/링크/제어문자 처리와 Discord Embed 크기 예산을 유지합니다.
긴 파일 목록과 원문은 제한 내에서 표시하며 생략 사실을 숨기지 않습니다. Discord 클라이언트별 실제 폭·줄바꿈은 별도 확인 대상입니다.

## Northflank 적용값

기존 토큰·AI 설정·관리자 ID·저장 경로를 유지하고 새 코드를 한 replica로 배포하세요.
실제 Northflank 설정은 이 작업에서 변경하지 않았습니다.

| 변수 | 적용값 | 의미 |
| --- | --- | --- |
| `DELETION_PUBLIC_LOG_ENABLED` | `1` | 기존 기록 채널로 송신 |
| `DELETION_PUBLIC_LOG_INCLUDE_CONTENT` | `1` | 원문과 콘텐츠 메타데이터 허용 |
| `DELETION_PUBLIC_LOG_REGISTERED_SOURCE_CONTENT` | `1` 또는 미설정 | 승인된 기존 명시 원본 전체 공개. 새 기본값 `1` |
| `DELETION_PUBLIC_LOG_PRIVATE_FULL_SOURCE_IDS` | 기존 값 또는 빈 값 | 기본 전체 승인에서 추가 목록 불필요. 전체 승인 `0`일 때만 V8 선택 승인 용도로 사용 |
| `DELETION_LOG_ALL_GUILD_CHANNELS` | 기존 값 유지 | 자동 감시 범위. 비공개 원본 공개 승인을 확대하지 않음 |
| `DELETION_LOG_EXTRA_SOURCE_CHANNEL_IDS` | 기존 값 유지 | 추가 원본. 독자 범위 검사 유지 |

기존 `ENABLED=1`, `INCLUDE_CONTENT=1`을 사용 중이면 **전체 원본 ID 목록을 새로 작성할 필요가 없습니다.**
새 전체 승인 플래그는 정확한 `1`일 때 켜지고 잘못된 값은 `0`으로 처리합니다.
`PRIVATE_FULL_SOURCE_IDS`를 비우기만 해서는 기본 전체 명시 원본 승인이 꺼지지 않습니다.

일반 회원이 기존 기록 채널을 실제로 읽을 수 있는지는 운영자가 Discord에서 확인합니다.
이 패치는 원본 채널이나 기록 채널의 접근 권한을 자동으로 변경하지 않습니다.
Message Content Intent의 Developer Portal 활성화·승인·실제 본문 수신도 확인하세요.

## 유지되는 경계와 보존

원문 공개는 승인된 Discord 카드에 한정합니다. stdout·예외 텔레메트리·장기 JSON/Pickle·관리 내역에는 원문·파일 URL을 저장하지 않습니다.
삭제 전 메모리 스냅샷·raw/cached/bulk 단일 파이프라인·TTL/상한·중복 방지·전송 실패 분리는 유지합니다.
메시지 삭제 API 실패를 성공으로 기록하지 않고 알려지지 않은 삭제 주체를 추측하지 않습니다.
첨부 메타데이터는 남겨도 파일 바이트를 자동 보관하거나 삭제 후 URL의 지속성을 보장하지 않습니다.

Discord에 게시된 카드는 메모리 TTL과 무관하게 남습니다. 기록 채널 열람자·보관 기간·기존 카드 삭제는 운영자가 관리합니다.
원본이 비공개여도 승인된 명시 원본의 삭제 콘텐츠는 공용 기록에서 보이므로 해당 기록 정책을 서버 운영에 반영하세요.

기존 검열·즉시 수정 검열·72시간/96시간 재검사·파딱 ID 인증·cleanup UI 비노출 및 내부 서비스·AI·XP·타이핑·슬래시 정책은 변경하지 않습니다.

## 검증과 실제 서버 확인

최종 로컬 실행은 **457개 통과, 실패 0, 스킵 0** (17.543초)입니다.
`python -m unittest discover -s tests -v`, `python -m compileall -q .`, `git diff --check`를 모두 통과했습니다.
기존 V8 기준 440개를 보존하면서 전체 승인·복귀 정책 9개와 UI 안전성 8개를 추가했습니다.
등록 원본 18개 전체와 실제 main import/생성자 기본값을 포함합니다. Python 3.12.14 / discord.py 2.7.1로 검증했으며 Python 3.13 실행은 미검증입니다.
실제 Northflank 배포·Discord Gateway 전달·일반 계정 열람·모바일/데스크톱 화면은 로컬 모의 테스트와 구분합니다.

운영 수용 검사는 다음 순서로 수행합니다.

1. 명시 `moderator-only`에 `시321133발`을 입력해 검열 삭제 후 기존 공용 기록에 정확한 원문과 실측 사유가 한 번 표시되는지 확인합니다.
2. 일반 계정으로 같은 카드를 열어 원문·작성자·채널·ID·KST를 읽고 간결한 순서와 모바일 줄바꿈을 확인합니다.
3. 명시 원본의 일반 삭제, 수정 검열, 스티커/이미지/파일·첨부만 메시지·일괄 삭제를 확인합니다. 빈 미디어 항목은 보이지 않아야 합니다.
4. 미등록 비공개 채널에서 같은 시험을 해 공용 카드가 생기지 않는지 확인합니다.
5. 스냅샷 없는 raw 삭제는 원문 확인 불가로 표시되고 과거 본문을 지어내지 않는지 확인합니다.
6. `REGISTERED_SOURCE_CONTENT=0`과 빈 개별 목록으로 V8 기본 메타데이터 복귀, `INCLUDE_CONTENT=0`으로 전역 가림을 시험한 뒤 승인된 값으로 복원합니다.
7. 목적지 권한 부족/API 실패에서 원래 검열은 계속되고 stdout·상태 파일에는 원문·파일 URL이 없는지 확인합니다.
8. AI·XP·타이핑·파딱 인증·cleanup 숨김·수정 검열/주기 검사를 기존 운영 시나리오대로 확인합니다.

## 롤백

기존 선택 승인 방식으로 돌아가려면 `DELETION_PUBLIC_LOG_REGISTERED_SOURCE_CONTENT=0`을 설정하고
`DELETION_PUBLIC_LOG_PRIVATE_FULL_SOURCE_IDS`의 기존 승인 목록을 확인한 뒤 재시작합니다.
모든 콘텐츠를 가리려면 `DELETION_PUBLIC_LOG_INCLUDE_CONTENT=0`, 로그 송신만 끄려면 `DELETION_PUBLIC_LOG_ENABLED=0`입니다.
모두 검열 삭제 자체는 유지합니다. 이미 공용 채널에 게시된 원문 카드는 환경변수/코드 롤백으로 사라지지 않으며 운영자가 별도 삭제해야 합니다.
코드·배포 이미지·데이터 백업 절차는 [Northflank 운영 문서](NORTHFLANK_OPERATIONS.md)를 따릅니다.
